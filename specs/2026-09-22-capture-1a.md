# Stage 1a capture: read the head on a Pi

**Status:** specified 2026-09-22, not started. Unblocked: Jared has a spare Pi, the
white LED, the driver and the ColorChecker are ordered.
**Shape:** one branch (`claude/capture-1a`, off `main`), one PR. Not merged by an agent.

## Why

`spectra` has CAD, colour maths and a fitter, and not one line that reads the sensor.
Nothing in the roadmap's Stage 1a rows can be measured until something does. The
BOM lists an ESP32, which would mean writing firmware; a Pi with Blinka runs the
Adafruit CircuitPython libraries for both chips as plain Python, so the capture
code lives in this package, is tested on the Mac with fakes, and runs unchanged on
the Pi. That is the whole reason to do it this way. Ruled 2026-09-22
(`docs/DECISIONS.md`).

grow-lab has a register-level AS7341 driver (`pi/drivers/as7341.py`). It is not
used here: it is async, bound to grow-lab's data models, and grow-lab depends on
this repo, so importing it would be circular. Adafruit's library is the native
mechanism and it is maintained.

## Hardware, as ordered

- Raspberry Pi (model unspecified; anything Blinka supports), I2C and SPI enabled.
- AS7341 breakout: Adafruit STEMMA QT #4698, on I2C at 0x39. Its own board, not the
  one in the grow-lab station. Calipered dimensions live in `components`.
- LED driver: Adafruit 1455, TLC59711, 12 channels of 16-bit constant current. Driven
  over SPI (Blinka `board.SCK` / `board.MOSI`; no MISO). Channel assignment: the
  white LED (Cree C513A) on channel 0. The seven colours (ruled set in
  `hardware/BOM.md`) on channels 1 to 7, wired but unused until Stage 1b.
- The head itself is whatever `spectra.cad` prints; capture does not care.

## What gets built

A package `spectra/capture/`:

- `hw.py`: two Protocols and their real implementations.
  - `Sensor`: `configure(gain, atime, astep)`, `read() -> Channels` where `Channels`
    is a frozen dataclass of ten ints: `f1` (415) through `f8` (680), `clear`, `nir`.
    Real class wraps `adafruit_as7341.AS7341`. Reading all eight F channels takes two
    SMUX passes in that library (`all_channels` does it); use that, do not roll our own.
  - `Lamp`: `set(channel: int, level: float)` with level 0 to 1, and `off()`. Real
    class wraps `adafruit_tlc59711.TLC59711`. Level maps to the 16-bit PWM word.
  - `FakeSensor` and `FakeLamp` for tests and for `--fake` on the command line. The
    fake sensor returns dark counts when the fake lamp is off and a fixed spectrum
    scaled by the lamp level when it is on, with a small deterministic noise term so
    the repeatability report has something to report.
- `cycle.py`: the measurement, hardware-agnostic.
  - `dark(sensor, lamp, n)`: lamp off, settle, `n` reads averaged.
  - `white(sensor, lamp, channel, level, n)`: lamp on, settle, `n` reads averaged. The
    caller has the white reference on the port. For 1a the white reference is the
    ColorChecker's white patch (19), ruled 2026-09-22; the PTFE tile is a 1d item.
  - `sample(sensor, lamp, channel, level, n)`: same, with the sample on the port.
  - `reflectance(sample, dark, white) -> tuple[float, ...]`: `(S - D) / (W - D)` per
    channel. Division by a non-positive denominator is an error, not a NaN.
  - Saturation: any channel at or above 90% of full scale for the configured ADC
    depth aborts the read with a message that names the channel and says to lower
    the gain. This is a hard stop; a saturated white makes every reflectance wrong.
  - Settle time after a lamp change is a parameter, default 0.2 s, labelled ESTIMATE
    in its docstring. It is not known and it goes in the session record so a later
    run can tell what it was measured under.
- `session.py`: one capture session is one directory.
  - `session.json`: started timestamp, spectra version, git sha if available, sensor
    settings (gain, atime, astep, integration time in ms), lamp channel and level,
    settle time, averaging `n`, the dark and white vectors, and free-text `notes`.
    Everything a later reader needs to reproduce or distrust the numbers.
  - `readings.csv`: one row per sample read. Columns, in this order:
    `sample_id, ts, f1, f2, f3, f4, f5, f6, f7, f8, clear, nir, r_f1 ... r_f8`. The
    first ten are raw counts, the last eight are reflectance against the session's
    white. `sample_id` is whatever the operator typed. `spectra.cgats.parse_csv`
    (PR #7) will not read this yet, because it has no RGB triple; the fitter that
    maps eight channels to XYZ is the next spec, not this one.
- `__main__.py`: `python -m spectra.capture` with subcommands.
  - `session new DIR [--gain --atime --astep --n --settle --notes]`: takes the dark,
    prompts for the white, takes the white, writes `session.json`.
  - `session read DIR SAMPLE_ID [--n]`: one sample, appends a row. Prompts "sample on
    the port, Enter" before reading unless `--no-prompt`.
  - `repeat DIR SAMPLE_ID --count 10`: the first acceptance row of Stage 1a. Reads the
    sample `count` times, prompting "lift and replace the head, Enter" between reads.
    Appends every row, then prints per-channel mean, standard deviation and
    coefficient of variation of the reflectance, and the worst channel. ΔE00 spread
    needs the eight-channel fitter and is reported by the next spec; say so in the
    output rather than printing nothing.
  - `--fake` on every subcommand swaps in the fakes, so the whole CLI runs on the Mac.
- `pyproject.toml`: a `pi` extra: `adafruit-blinka`, `adafruit-circuitpython-as7341`,
  `adafruit-circuitpython-tlc59711`. Pin each to the current release with `>=`.
  Nothing in the base list changes.
- `README.md`: a section "Stage 1a on the Pi": enable I2C and SPI, `pip install -e
  .[pi]`, the wiring in five lines, the three commands in order. Then a line saying
  how to try it on the Mac with `--fake`.
- `tests/test_capture.py`: the cycle maths (reflectance, saturation abort, the zero
  denominator), the session round trip (write, read back, same numbers), and a CLI
  run end to end with `--fake` in a temp dir that asserts a `readings.csv` with the
  right header and `count` rows. No test imports the Adafruit libraries; `hw.py`
  imports them lazily inside the real classes so the package imports on a machine
  without them.

## What is not built

- The eight-channel to XYZ fitter and the ΔE00 acceptance rows. Next spec.
- Sequential capture across the LED ring (1b). The `Lamp` protocol already takes a
  channel, so 1b is a loop, not a redesign.
- Auto-gain. The operator sets gain; the saturation abort tells them when it is wrong.
- Any store, database or sample registry (1c).
- Anything that touches the ESP32.

## Done test

- `.venv/bin/python -m pytest -q` green on the Mac, with the existing 95 still passing.
- `python -m spectra.capture --fake session new /tmp/s && python -m spectra.capture
  --fake repeat /tmp/s black-pla --count 10` runs on the Mac and prints a spread table.
- `python -c "import spectra.capture"` succeeds without the Adafruit libraries
  installed.
- The PR body lists what the Pi run still owes: the real settle time, the gain that
  does not saturate the white patch under the C513A at the level chosen, and the
